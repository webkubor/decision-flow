# DECISION_FLOW 1.0 — 选型决策闭环

> 目的不是「选出对的那个」，而是**让「做选择的依据」越来越可靠**。
> 每个选择都是一个可证伪的假设；用同一套最小任务实测，用固定字段复盘，靠数据迭代而不是靠感觉。
> 走错方向也是有效数据——**只要闭环在跑，往哪走都是往前走**。

## 0. 怎么用这个仓

```
templates/    每次决策复制一份卡片
records/      每轮复盘的落盘记录（不可删除，只追加）
scripts/      校验脚本，保证字段同构、可跨轮对比
```

一轮 = 一个 `records/<YYYY-MM-DD>-<slug>.md`，内容从 `templates/decision-card.md` 复制。

## 1. 五步循环（S・H・M・P・R）

| 步 | 动作 | 产出 |
|---|---|---|
| **S 圈定对象** | 这次比什么；候选 ≤ 3 个（宁缺毋滥）；说清"比的是什么层" | 候选清单 + 比什么的一句话定义 |
| **H 写假设** | 每个候选一条可证伪声明：在[场景]下，用[X]能让[主指标]达到[目标] | 每候选一条假设句 |
| **M 定指标** | 1 个主指标 + 2~3 个护栏指标 + 记录口径（怎么量、量几次） | 指标定义与阈值 |
| **P 最小试点** | **同一个**真实小任务，各候选各跑一遍，产出同一形态的最小产物 | 产物 + 数据 |
| **R 复盘 + 升版** | 只摆数据不争论感觉；写"验证/推翻了什么"进经验库；Flow 升版 | 记录文件 + 经验条目 |

## 2. 每次必记的 7 个字段（同构才能跨轮比）

| 字段 | 含义 | 记什么 |
|---|---|---|
| **P-1 场景** | 这次任务是什么 | 一句话 + 任务链接/路径 |
| **P-2 耗时** | idea → 可用 demo | 小时数 |
| **P-3 成本** | token / 金额 | 元 + token 数 |
| **P-4 返工** | 第几次才首次通过 | 首跑是否通过 + 返工轮次 |
| **P-5 排障** | 出错后谁修的、花多久 | 自修/AI 修 + 小时数 |
| **P-6 分发** | 产物给别人要几步、体积多大 | 步数 + 体积/大小 |
| **P-7 结论** | 这次验证了什么 | 验证/推翻 + 一句话 |

## 3. 迭代规则（防变形）

1. **主指标一票优先**：主指标没达标就淘汰，不许用护栏指标救场。
2. **同任务同指标**：候选必须跑**同一个**任务、同口径测量，否则数据不可比。
3. **无数据不拍板**：主观项（思维强度 / 知识库质量 / GEO 效果）一律用同一套任务实测，
   不准用"感觉"、单条评测帖或 star 数代替。
4. **结果即经验**：淘汰的候选不是"错的"，是"在这个主指标下没达标"，写进经验库。
5. **只追加不覆盖**：`records/` 里的历史不可删改，只能新增轮次，避免幸存者偏差。
6. **一次只比一层**：模型 / 技术栈 / Agent 工作流是三层，不混在一张卡里比。

## 4. 分层指标参考

### A. 客观硬指标（机器可测，优先）
- 生态活跃度：star、最近 30 天 commit 频率、贡献者数、**issue 中位关闭时间**
- 成熟度：版本号、是否有人真在生产用、依赖树深度与体积
- 性能基准：冷启动、内存占用、构建时长（以官方 benchmark 为准）
- 成本：基础设施 / 订阅 / 单次运行成本（元·月 或 元·千次）

### B. 半客观（有明确判据，0–5 打分）
- **AI 可维护性**：TS 偏置、类型覆盖、报错可读性（所有权在 AI 时这条权重最高）
- **GEO 能力**：JSON-LD、SSR/预渲染、llms.txt 可做性、内容可索引性
- **分发形态**：能否单二进制 / 零依赖 / 跨平台
- **知识库接入度**：官方文档量、示例覆盖、教程数（决定 AI 按它写代码时少翻车）

### C. 主观但必须实测
- **思维/深度差异**：同一组真实任务跑分，看谁首跑就对、要返工几次
- **上手成本**：从 clone 到跑通首个 demo 的时长

## 5. 经验库（跨轮沉淀）

每次 R 步把验证过的结论追加到 `records/_lessons.md`：
- `[YYYY-MM-DD] <结论>（来源：<记录文件名>）`
